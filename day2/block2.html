Lab 2: Why did CI fail?

Goal: use AI to find the real cause of a failed build, and not just make it green. About 30 minutes.

Folder: day2\block2. Three failed builds. Each has a long log (failureN-ci.log) and the change that triggered it (failureN-changes.diff). Failure 2 also has its workflow file.

Causes can be: code bug, config problem, flaky test, dependency change, or infra glitch.

Do each failure the same way

📝 EDITOR
Open failure1-ci.log. It is 200+ lines. Do not read it all. Find the line that says FAILED.
💬 COPILOT CHAT
Give Copilot the log AND the change:
Here is a failed CI run: #file:failure1-ci.log and the change that triggered it: #file:failure1-changes.diff
1. What is the root cause? Quote the exact log line that proves it.
2. Is it a code bug, config, flaky test, dependency or infra problem?
3. What is the smallest fix?
4. What would make you wrong?
Predict first: Before you read the answer, say out loud: which file do you suspect? Then compare.
📝 EDITOR
Check the quoted log line really exists in the log (Ctrl+F). If it does not, Copilot made it up. Tell it.

Repeat for failure2 (also give it #file:failure2-workflow.yml) and failure3.

Failure 3: run-to-run it passes and fails on the same code. What does that tell you? Do not accept "add a retry" or "skip the test" as the fix.

Check yourself

⭐ Takeaway

CI logs are 95% noise. Ask the AI for the proof line, then check it yourself. A confident wrong cause is worse than no answer. The change that triggered the build is often not the one that broke it.

Reusable prompt:

Here is a failed CI run: #file:LOG and the change: #file:DIFF
1. Root cause, quoting the exact log line.
2. Class: code / config / flaky / dependency / infra.
3. Smallest fix.
4. What evidence would prove you wrong?
