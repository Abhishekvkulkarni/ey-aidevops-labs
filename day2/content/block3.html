Lab 3: Release notes you can trust

Goal: let AI draft release notes, then catch what it got wrong. About 20 minutes.

File: day2\labs\block3-release-notes\commits.txt: 16 commits for Shipwave API v2.4.0, with diffs. Some commit messages do not tell the whole story.

🤖 What AI adds
Reads 16 commits and their diffs, drafts customer-facing notes in seconds, and flags where a message and its diff disagree. By hand: reading 16 diffs line by line.
🧠 What only you add
Judging what a customer must know: breaking changes, the security fix, and what an operator must run before deploying.

Copilot Chat must be in Agent mode (mode picker at the bottom of the chat box). If it asks to run a command, click Allow. You do not need to open a terminal in this lab.

Step 1: one prompt, two passes

💬 COPILOT CHAT (Agent mode)
Paste:
Read #file:commits.txt (16 commits for Shipwave API v2.4.0). Write customer-facing release notes twice.
Pass 1: using only the commit subjects.
Pass 2: reading the diffs.
Sections: Breaking changes, Security, New, Fixed, Upgrade notes. End every bullet with the commit hash. Leave out reverted and internal-only changes. Only use what the commits show.
Then list (a) every commit whose message does NOT match its diff, and (b) every bullet that changed between pass 1 and pass 2.
Predict first: What will pass 1 miss if it only reads the subjects?

Step 2: you are the reviewer

Tick each box only after YOU have checked it in the Pass 2 notes. Do not ask Copilot.

Your review checklist

⭐ Takeaway
AI release notes are only as good as what you feed them. Messages lie; diffs do not. Always read the diff of anything labelled "typo", "cleanup" or "refactor".

Reusable prompt:

Write customer-facing release notes from these commits and diffs. Sections: Breaking changes, Security, New, Fixed, Upgrade notes. Cite the commit hash on every bullet. List any commit whose message does not match its diff. Leave out reverted and internal-only changes. Do not invent anything.
