Lab 2: Why did CI fail?

Goal: use AI to find the real cause of failed builds, not just make them green. About 20 minutes.

Folder: day2\labs\block2-ci-failures. Three failed builds. Each has a long log (failureN-ci.log, 200+ lines), the change that triggered it (failureN-changes.diff) and recent run history (failureN-history.txt). Failure 2 also has failure2-workflow.yml. Failure 3 also has failure3-cache.py and failure3-test_cache.py.

Causes can be: code bug, config problem, flaky test, dependency change, or infra glitch. Do not read the logs yourself first.

🤖 What AI adds
Reads about 670 lines of logs, diffs and history in seconds and names the likely cause with a proof line. By hand: scrolling hundreds of log lines per failure.
🧠 What only you add
Checking the proof line against the real log, and knowing that a retry or a skipped test is not a fix.

Copilot Chat must be in Agent mode (mode picker at the bottom of the chat box). If it asks to run a command, click Allow. You do not need to open a terminal in this lab.

Step 1: triage all three at once

💬 COPILOT CHAT (Agent mode)
Paste:
The folder day2/labs/block2-ci-failures has 3 failed CI runs. For each failure N, read failureN-ci.log, failureN-changes.diff and failureN-history.txt. Also read failure2-workflow.yml for failure 2, and failure3-cache.py and failure3-test_cache.py for failure 3.
Give me one table, one row per failure, with these columns:
1. Root cause
2. The exact log line that proves it, with its line number
3. Class: code / config / flaky / dependency / infra
4. Smallest fix
5. What evidence would prove you wrong
Do not suggest a retry or skipping a test.
Predict first: Before reading the table, say out loud what kind of cause you expect for each failure (code, config, flaky...). Good output has a different kind of cause per row, and a log line plus line number in every row.

Step 2: verify, do not trust

📝 EDITOR
Pick one row. Open that failureN-ci.log and press Ctrl+G, type the line number. Is the quoted line really there? If not, Copilot made it up: tell it.

Step 3: the hard one

💬 COPILOT CHAT (Agent mode)
Failure 3 passes and fails on the same code. Paste:
For failure 3, show me the exact line in failure3-test_cache.py that makes it flaky, and propose a fix that is deterministic. No retry, no skipping the test. Do not change the production code if the test is the problem.

Check yourself

⭐ Takeaway
CI logs are 95% noise. Ask the AI for the proof line with its line number, then check it yourself. A confident wrong cause is worse than no answer. The change that triggered the build is often not the one that broke it, and the run history is evidence too.

Reusable prompt:

Here are failed CI runs: #file:LOG #file:DIFF #file:HISTORY (plus workflow/code if relevant). For each: root cause with the exact log line and line number; class (code/config/flaky/dependency/infra); smallest fix; what evidence would prove you wrong. Do not suggest a retry or skipping a test.

If stuck: Copilot cannot find the files? Open day2\labs\block2-ci-failures in the Explorer and drag the folder into the chat box, then paste the prompt again.
