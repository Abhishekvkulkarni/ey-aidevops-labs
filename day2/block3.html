Lab 3: Release notes you can trust

Goal: let AI draft release notes, then catch what it got wrong. About 30 minutes.

File: day2\block3\commits.txt: 16 commits for Shipwave API v2.4.0, with diffs. Some commit messages do not tell the whole story.

Step 1: from messages only

💬 COPILOT CHAT
Write customer-facing release notes for Shipwave API v2.4.0 from the commit subjects in #file:commits.txt. Sections: Breaking changes, Security, New, Fixed, Upgrade notes. End every bullet with the commit hash. Only use what the commits show.
Predict first: What will it miss if it only reads the subjects?

Step 2: now from the diffs

💬 COPILOT CHAT
Redo the release notes, this time read the diffs, not just the messages. List any commit whose message does NOT match what its diff actually does. Leave out reverted and internal-only changes.

Step 3: you are the reviewer

Check each of these yourself. Do not ask Copilot.

⭐ Takeaway

AI release notes are only as good as what you feed them. Messages lie; diffs do not. Always read the diff of anything labelled "typo", "cleanup" or "refactor".

Reusable prompt (put it in your release workflow):

Write customer-facing release notes from these commits and diffs. Sections: Breaking changes, Security, New, Fixed, Upgrade notes. Cite the commit hash on every bullet. List any commit whose message does not match its diff. Leave out reverted and internal-only changes. Do not invent anything.
