1. Concept 10 min · trainer (Anil) leads

Same AI, same app. The only thing that changes is how you ask.

Basic prompt

Containerize and deploy the Shipwave API to Kubernetes with Helm.

The AI fills every gap with its own defaults. You find out what it chose after it breaks, or after a scanner flags it.

Spec-driven

A short markdown file with numbered requirements and acceptance checks.

The AI has no gaps to guess in, and you have a checklist that proves whether it followed the spec.

What AI does by default (seen in real reviews)

DefaultWhy it hurts
FROM python:latestNot reproducible, drifting vulnerabilities
Container runs as rootAny breakout starts with full privileges
API_KEY in values.yamlSecret ends up in Git
No probes, no resource limitsBad pods stay in rotation, one pod can starve a node
Today's thread: trust but verify, with numbers. Every lab has a checker. You score the AI, the AI does not score itself.

3. Solo challenge 30 min · you work alone

Deploy your spec-driven API to your namespace and pass acceptance checks A2 to A6 from the spec.

Create the Secret by hand (it is not part of the chart) 
kubectl -n $env:NAMESPACE create secret generic shipwave-secrets --from-literal=api-key=demo-key-123
Build, push, check the user, scan
Use the commands in the A2 and A3 boxes under Paste and check. Fix and rebuild until both pass.
Lint and install the chart
Use the A4 and A5 boxes. If a pod is not Ready, kubectl -n $env:NAMESPACE describe pod tells you why. Ask Copilot to fix it, but read its diff before accepting.
Call the health endpoint
Use the A6 box. Two terminals: one keeps the port-forward open.
Stretch (finished early?): write a spec for the worker yourself, using the API spec as a model. Ask Copilot to implement it, then check it the same way (A2, A3, A5).
